# Техническое задание
## Веб-платформа для взаимодействия с мебельными сборщиками (сервис-исполнителями)

---

## 1. Цель и суть проекта

Веб-приложение (маркетплейс/личный кабинет), связывающее компанию (заказчика работ) со сборщиками мебели (подрядчиками, физлицами/самозанятыми/ИП). Компания публикует заявки на сборку (в первую очередь — кухни), сборщики откликаются, выполняют работу и подтверждают её фотоотчётом. Система должна дать контроль качества, прозрачность истории работ по каждому сборщику и упростить учёт/расчёт оплаты.

**Роли пользователей:**
- **Сборщик** — исполнитель, проходит регистрацию и верификацию, откликается на заявки, выполняет работы, загружает фотоотчёт.
- **Менеджер компании** — создаёт заявки, принимает/отклоняет фотоотчёты.
- **Администратор** — модерация анкет сборщиков, управление справочниками, доступ ко всей системе, аналитика.

Клиентской роли в системе нет — заявки создаёт только компания, конечный заказчик кухни в приложении не участвует.

Работа ведётся в одном регионе. В заявке указывается место (адрес/район) выполнения работ — сборщик сам решает, откликаться на неё или нет, исходя из удобства/удалённости.

## 2. Регистрация и профиль сборщика

### 2.1 Обязательные данные при регистрации

**Личные данные:**
- ФИО (полностью, как в паспорте)
- Дата рождения
- Номер телефона (с подтверждением через SMS-код)
- Email
- Фото профиля (селфи, для идентификации при встрече с клиентом)

**Паспортные данные:**
- Серия и номер паспорта
- Кем выдан
- Дата выдачи
- Код подразделения
- Дата рождения, место рождения
- Адрес регистрации
- Адрес фактического проживания
- Фото/скан паспорта (разворот с фото + страница с пропиской)

**Налоговый/юридический статус** (критично для расчётов и легальности):
- Статус: физлицо / самозанятый (НПД) / ИП
- Если самозанятый — ИНН + справка о постановке на учёт НПД (можно проверять через API ФНС "Мой налог")
- Если ИП — ОГРНИП, реквизиты
- Согласие на обработку персональных данных (обязательный чекбокс, отдельный документ-оферта)

**Реквизиты для оплаты:**
- Номер карты или банковские реквизиты (для безналичного расчёта)
- Опционально: СБП-номер телефона
- Если расчёт наличными — сборщик должен указать адрес, куда нужно подъехать для передачи денег (плюс желаемое время/контакт)

**Профессиональные данные:**
- Специализация (кухни / шкафы-купе / корпусная мебель / встроенная техника и т.д. — мультивыбор)
- Стаж работы
- Наличие своего инструмента (да/нет, список)
- Наличие автомобиля (важно для габаритной мебели/инструмента)
- Регион/город работы, готовность к выездам в другие районы

**Дополнительно можно добавить:**
- Контакт для экстренной связи

### 2.2 Модерация анкеты
- После заполнения анкета уходит в статус «На проверке»
- Администратор проверяет документы (сверка ФИО, читаемость сканов, соответствие фото)
- Статусы анкеты: `Черновик → На проверке → Подтверждён → Отклонён (с указанием причины) → Заблокирован`
- Без подтверждённого статуса сборщик не видит заявки/не может откликаться

### 2.3 Требования по 152-ФЗ (важно, т.к. паспортные данные — персональные данные)
- Хранение сканов паспорта — в зашифрованном виде, доступ только у ограниченного круга (админ)
- Отдельная политика обработки персональных данных, согласие фиксируется с датой/временем/IP
- Логирование доступа к паспортным данным (кто и когда открывал скан)
- Желательно — размещение сервера в РФ (если работаете с гражданами РФ, требование о локализации ПДн)
- Автоматическое обезличивание/удаление данных при длительной неактивности аккаунта (по запросу пользователя — право на удаление)

## 3. Заявки на сборку

### 3.1 Создание заявки (менеджер)
Поля заявки:
- Тип мебели (кухня / шкаф-купе / гардеробная и т.д.)
- Адрес объекта (с картой)
- Дата и желаемое время выполнения
- Срок выполнения работы (крайний срок сдачи — дата/время, до которого должен быть загружен фотоотчёт; на его основе система может показывать просрочку)
- Срочность (обычная / срочная)
- Модель/чертёж кухни, спецификация от Базис (можно прикрепить PDF/фото схемы сборки)
- Габариты, количество модулей
- Стоимость работы (фиксированная или расчётная по прайсу — модули × ставка)
- Комментарий/особые условия (например, "нужен монтаж встроенной техники", "второй этаж без лифта")
- Контактные данные клиента на объекте (телефон, ФИО)
- Требуемая специализация исполнителя

### 3.2 Логика распределения заявок

**Первый отклик = бронирование, затем подтверждение админом.** Заявка публикуется и видна всем подтверждённым сборщикам. Кто первый нажал «Беру в работу» — тот резервирует заявку (статус «Забронирована»), заявка сразу пропадает из списка доступных для остальных. Далее администратор должен подтвердить бронь (статус «Подтверждена админом») — только после этого заявка официально переходит в работу.

Важные технические нюансы для реализации:
- Нужна защита от гонки (race condition) — если два сборщика нажмут кнопку почти одновременно, забронировать должен строго один (транзакция/блокировка на уровне БД, а не просто проверка на фронте).
- После бронирования остальным, кто пытается открыть эту заявку, сразу показывается статус «уже забронирована».
- Если админ не подтверждает бронь (например, есть сомнения по сборщику) — заявка возвращается в пул, доступный остальным.

**Если сборщик пропал** (забронировал заявку, но не выходит на связь / не появляется на объекте / не сдаёт работу в срок) — менеджер/админ снимает с него заявку, а сам сборщик **блокируется** в системе (не просто предупреждение — блокировка аккаунта, без возможности откликаться на новые заявки). Разблокировка — вручную администратором при необходимости.

### 3.3 Статусы заявки
```
Новая → Опубликована → Забронирована (первым откликнувшимся) → Подтверждена админом →
В работе → Фотоотчёт загружен → Принята менеджером → Закрыта
                                      ↓
                              Отклонена (доработка) → В работе

Также: Отменена менеджером, Бронь снята (сборщик пропал → возврат в пул + блокировка сборщика), Спор/рекламация
```

## 4. Фотоотчёт по завершении работ

**Обязательный набор фото** (реализовать как слоты-подсказки, а не просто общую загрузку — так отчёты будут единообразны и удобны для проверки):

1. Общий вид кухни целиком (1-2 фото, с двух ракурсов)
2. Каждый модуль крупным планом, с открытыми фасадами/ящиками
3. Встроенная техника (духовка, варочная панель, вытяжка и т.п.) — после установки/подключения
4. Столешница и мойка/смеситель
5. Примыкания — стыки со стеной, потолком, плинтуса, зазоры
6. Убранное рабочее место (упаковка/мусор вывезены)

Опционально: фурнитура крупным планом (петли, направляющие), остатки неиспользованных материалов/крепежа.

- Чек-лист перед сдачей (чекбоксы, обязательны к отметке):
  - Все модули собраны согласно схеме
  - Фасады и ящики открываются/закрываются без перекоса
  - Техника установлена и подключена (если входило в заявку)
  - Мебель выровнена, устойчива
  - Место убрано от мусора/упаковки
- Комментарий сборщика (что сделано, есть ли нюансы/недостающие детали)
- Автоматическая метка даты/времени загрузки, желательно — геолокация (для подтверждения, что фото сделаны на объекте)

**После загрузки:**
- Менеджер получает уведомление, проверяет фото и чек-лист
- Менеджер прикрепляет **акт приёма-передачи** (файл — скан/PDF, либо формируется по шаблону в самой системе) — это обязательный шаг на статусе «В работе»/при закрытии заявки, без прикреплённого акта заявку нельзя перевести в статус «Закрыта»
- Принимает работу → статус «Закрыта», акт становится доступен сборщику для просмотра/скачивания в его личном кабинете (в карточке соответствующей заявки)
- Либо отклоняет с комментарием → заявка возвращается сборщику на доработку

## 5. Оплата и рейтинг

- Оплата **фиксированная**, указывается в самой заявке при её создании (менеджер вводит сумму вручную или она подтягивается из Bitrix24, см. п.8).
- Сама выплата происходит **вне системы** — обычным переводом. Приложение фиксирует только факт «заявка закрыта → сумма к выплате», без интеграции с платёжными сервисами.
- История заявок и сумм у сборщика в личном кабинете (что выполнено, какая сумма причиталась) — для его собственного учёта.
- Акт выполненных работ формировать не нужно (пока не требуется).
- Рейтинг сборщика: формируется на основе — оценки менеджера после каждой заявки, отсутствия рекламаций, соблюдения сроков.
- История всех заявок сборщика — доступна администратору и самому сборщику.

## 7. Админ-панель

- Модерация анкет сборщиков (одобрение/отклонение документов)
- Управление заявками (просмотр всех, ручное переназначение, отмена)

## 8. Технические требования (черновой вариант)

Учитывая твой стек — предлагаю:
- **Backend:** Laravel (раз уже изучаешь — хороший проект для практики), либо Bitrix, если нужна интеграция с текущей CRM компании
- **БД:** MySQL/PostgreSQL
- **Хранилище файлов:** отдельный S3-совместимый бакет (не публичный) для паспортных сканов — с ограничением доступа
- **Аутентификация:** телефон + SMS-код (сервис типа SMS.ru / SMSC) или email+пароль
- **Уведомления:** Telegram Bot API + MAX Bot API (уточнить доступность на момент разработки)
- **Карты:** Яндекс.Карты API или 2GIS API (есть опыт с 2GIS) — для отображения адреса заявки
- **Мобильная адаптивность:** обязательна — сборщики будут пользоваться с телефона (фото грузят прямо с объекта), стоит рассмотреть PWA для оффлайн-черновиков фотоотчёта при плохом интернете на объекте
- **Интеграция с Bitrix24:** при создании заявки менеджером цена должна синхронизироваться из Bitrix24 (например, из сделки/каталога цен) в приложение — через REST API Bitrix24 (входящий вебхук или приложение-коннектор). Нужно уточнить:
  - Откуда именно берётся цена в Bitrix24 (карточка сделки / товар в каталоге / отдельный справочник)?
  - Синхронизация разовая (при создании заявки менеджер подтягивает актуальную цену кнопкой) или постоянная (автообновление, если цена в Bitrix24 меняется после создания заявки)?
  - Нужна ли обратная синхронизация (например, отметка в Bitrix24, что заявка на сборку закрыта)?

## 9. Этапы разработки (предложение MVP → v2)

**MVP:**
1. Регистрация/анкета сборщика + модерация админом
2. Создание заявок менеджером (с ручным вводом цены, срок выполнения)
3. Отклик сборщика на заявку — бронь по первому отклику + подтверждение админом
4. Загрузка фотоотчёта по слотам, акт приёма-передачи от менеджера, приёмка
5. Базовые уведомления (Telegram)
6. Блокировка сборщика при пропаже с забронированной заявки

**v2:**
1. Интеграция с Bitrix24 — синхронизация цен в заявку
2. Уведомления в MAX (если появится/доработается открытый Bot API)
3. Рейтинг сборщиков, история выполненных заявок
4. Интеграция с ФНС (проверка статуса самозанятости)
5. Аналитика/отчёты для админа

## 10. Открытые вопросы для уточнения перед стартом разработки

2. Сколько времени даётся сборщику на выход на связь/начало работ после подтверждения брони админом, прежде чем считать его «пропавшим» и блокировать?
3. Нужен ли лимит на количество одновременно забронированных заявок у одного сборщика (чтобы не набирал больше, чем может выполнить)?
4. Кто и как определяет минимальный обязательный набор фото для конкретного типа мебели (сейчас предложен набор для кухни — для других типов, возможно, потребуется другой набор)?
